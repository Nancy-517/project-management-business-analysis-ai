# 需求A_数据与规则处理

## 一、处理目标

本文件基于官方 `项目经营样例数据.md/xlsx`，说明项目经理经营会前AI工作台如何完成数据判断、风险分诊和客户反馈联动。

本次只输出内部经营会前的风险优先级，不输出确定性的亏损、责任或验收结论。

## 二、官方数据来源

| 数据表 | 字段 | 用途 |
| --- | --- | --- |
| 项目记录 | 项目编号、客户类型、项目阶段、预算、已发生成本、计划周期、已用天数、验收风险、质量问题数、客户满意度 | 计算成本、进度、质量和验收风险 |
| 客户反馈 | 项目编号、反馈摘要、问题标签、是否需人工复核 | 联动判断人工复核优先级 |
| 计算提示 | 成本使用率、周期使用率、质量风险、优先级 | 作为风险判断口径 |

## 三、计算规则

| 指标 | 计算方式 | 判断口径 |
| --- | --- | --- |
| 成本使用率 | 已发生成本 / 预算 | 超过90%且未验收，建议标记成本风险 |
| 周期使用率 | 已用天数 / 计划周期 | 超过90%且未验收，建议标记进度风险 |
| 质量风险 | 质量问题数>=3 或 客户满意度<3.8 | 需要人工复核 |
| 验收风险 | 验收风险字段为高，或验收前阶段存在材料版本问题 | 优先复核验收材料 |
| 客户反馈联动 | 客户反馈标记“是否需人工复核=是” | 提升复核优先级 |
| 综合优先级 | 成本、进度、质量、验收、客户反馈组合判断 | 风险越多，越优先处理 |

## 七、判断边界

- 成本使用率超过阈值只能说明需要复核，不代表项目已亏损。
- 周期使用率超过阈值只能说明进度风险，不代表项目责任归属。
- 验收风险为高或材料版本不一致时，AI不能直接判断验收通过或失败。
- 客户反馈用于提示复核优先级，不能被改写成未经确认的对外结论。
- 涉及成本、验收、责任归属和对外承诺的内容，必须进入人工复核记录。

## 八、AI处理逻辑设计

### 架构原则：Skill / Memory / Guardrail 三层解耦

本方案不把AI当成一次性报告生成器，而是把AI拆成”读取-计算-判断-生成-复核”的Prompt链，并在架构上将三类关注点严格分离：

- **Skill（可复用能力）**：下面的4个Prompt模板就是Skill——数据预处理、风险判断链、输出约束、人工反馈接入。它们不包含任何具体的项目数据，可以直接复用到不同客户的项目经营分析中。
- **Memory（动态上下文）**：P001-P008的项目记录、客户反馈、历史案例等材料是Memory——按客户动态注入到Skill中。换一家客户的数据，同一套Skill即可运行。
- **Guardrail（全局约束）**：规则与审核清单、主体责任边界、越权表述过滤器是Guardrail——不随客户变化，始终生效。

这种解耦使得工作台从”一次性定制交付”变成”可标准化复用的产品”，是工业级AI应用的关键架构选择。

### 1. 数据预处理Prompt

```text
你是项目经理经营会前资料整理助手。
请读取项目记录和客户反馈，按项目编号合并信息。
输出字段：项目编号、阶段、预算、已发生成本、计划周期、已用天数、验收风险、质量问题数、满意度、客户反馈、是否需人工复核、证据来源。
禁止补写材料中不存在的信息；缺失内容写“待补充”。
```

预期输出：项目级统一视图，避免周报、成本表、验收材料和客户反馈分散。

### 2. 风险判断链Prompt

```text
请基于项目级统一视图，严格按以下顺序判断：
1. 计算成本使用率=已发生成本/预算；
2. 计算周期使用率=已用天数/计划周期；
3. 判断质量风险：质量问题数>=3或满意度<3.8；
4. 判断验收风险：验收风险字段为高，或反馈提到材料版本/规则冲突；
5. 联动客户反馈：是否需人工复核=是时提升复核优先级。
输出：项目编号、触发规则、风险项、分诊结果、建议动作、证据来源。
```

该Prompt让AI按规则链处理，而不是直接凭印象判断“哪个项目危险”。

### 3. 输出约束Prompt

```text
所有结论只能作为内部经营会前参考。
不得输出“已亏损”“责任明确”“验收失败”“收益可提升”等确定性或承诺性表达。
涉及成本、验收、责任归属、对外承诺时，必须写成“建议复核/需要确认/待人工确认”。
如果证据不足，输出“证据不足，待补充”，不得编造结论。
```

该约束用于保证AI输出符合主体责任边界。

### 4. 人工反馈接入Prompt

```text
以下是人工复核意见：{人工意见}
请根据人工意见修正项目风险分诊。
要求：
1. 保留原AI判断和人工修正记录；
2. 标明哪些结论被确认、哪些被否决、哪些仍待补充；
3. 更新人工复核任务池；
4. 不删除证据链。
```

示例：若财务负责人确认 P002 成本超预算来自已批准的合同变更，则AI应把“成本异常原因待确认”改为“成本变化已由财务确认，仍需关注交付质量和验收风险”，但不能删除原始成本使用率记录。

### 5. P002处理示例

| Prompt链节点 | P002输出 |
| --- | --- |
| 数据预处理 | P002执行中，预算28万元，已发生成本31万元，计划45天，已用42天，验收风险高，质量问题5，满意度3.1，客户反馈要求复核 |

## 二、风险标签检查

| 标签 | 当前触发情况 | 处理 |
| --- | --- | --- |
| 数据异常 | P002成本超预算，P005客户要求解释成本变化 | 只提示复核优先级，不直接判断亏损 |
| 进度风险 | P001、P002、P005、P006周期使用率超过90% | 结合阶段和客户反馈进入分诊 |
| 质量风险 | P002、P005、P006质量问题数或满意度触发 | 项目经理确认质量问题是否关闭 |
| 验收风险 | P002、P005验收风险高；P006材料版本不一致 | 审核人复核验收材料版本和对外口径 |
| 范围过大 | 客户原始需求包含工作台、查询、提醒、盈亏、月报 | 收窄为经营会前风险分诊和月报草稿 |
| 隐私风险 | 样例数据不含真实身份、账号、密钥 | 提交前继续检查ZIP内容 |

## 三、主体责任检查

| 内容 | AI是否可直接定稿 | 处理方式 |
| --- | --- | --- |
| 风险分诊和优先级 | 可生成内部参考 | 经营会前供项目经理使用 |
| 成本异常原因 | 不可 | 财务负责人和项目经理复核 |
| 验收材料是否可对外提交 | 不可 | 审核人复核 |
| 项目亏损或责任归属 | 不可 | 授权负责人确认 |
| 客户对外承诺 | 不可 | 人工定稿 |

## 四、审核结论

新版提交包以”项目经理经营会前AI工作台”为主线，使用官方项目经营样例数据完成风险分诊，能够体现真实产业场景响应、AI原生结构设计、人机协同编排、轻量化验证和主体责任边界。

在架构层面引入了状态机式工作流（支持回退和降级）、防御性AI编程（每层有fallback策略）、Skill/Memory/Guardrail三层解耦（支持跨客户复用）、UX即护栏（界面约束AI行为边界）和Local-First（数据主权保障）等AI工程前沿设计。

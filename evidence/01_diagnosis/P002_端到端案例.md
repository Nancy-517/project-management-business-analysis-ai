# P002_端到端案例

## 一、案例目的

P002用于展示项目经理经营会前AI工作台如何从官方项目数据出发，经过风险识别、报告生成、人工复核和证据绑定，形成一个可执行的端到端工作流。

## 二、输入数据

| 字段 | P002数据 | 来源 |
| --- | --- | --- |
| 客户类型 | 咨询交付 | 项目经营样例数据-项目记录 |
| 项目阶段 | 执行中 | 项目经营样例数据-项目记录 |
| 预算万元 | 28 | 项目经营样例数据-项目记录 |
| 已发生成本万元 | 31 | 项目经营样例数据-项目记录 |
| 计划周期天 | 45 | 项目经营样例数据-项目记录 |
| 已用天数 | 42 | 项目经营样例数据-项目记录 |
| 验收风险 | 高 | 项目经营样例数据-项目记录 |
| 质量问题数 | 5 | 项目经营样例数据-项目记录 |
| 客户满意度 | 3.1 | 项目经营样例数据-项目记录 |
| 客户反馈 | 报告修改次数多，成本超预算仍未提前预警 | 项目经营样例数据-客户反馈 |

## 三、AI风险识别

| 判断项 | 计算/规则 | P002结果 | 结论 |
| --- | --- | --- | --- |
| 成本使用率 | 已发生成本/预算 | 31/28=110.7% | 触发成本风险 |
| 周期使用率 | 已用天数/计划周期 | 42/45=93.3% | 触发进度风险 |
| 质量风险 | 质量问题数>=3 或满意度<3.8 | 质量问题5，满意度3.1 | 触发质量风险 |
| 验收风险 | 验收风险字段为高 | 高 | 触发验收风险 |
| 客户反馈 | 是否需人工复核=是 | 是 | 提升复核优先级 |

AI输出：P002为高优先级项目，建议进入经营会优先复核。

## 四、报告生成

报告中采用谨慎表达：

> P002需经营会优先讨论，复核成本超预算原因、报告修改次数和交付风险。

报告中不使用以下表达：

- P002已经亏损。
- P002责任已经明确。
- P002验收失败。
- AI确认项目存在管理责任。

## 五、人工复核任务

| 复核事项 | 建议复核人 | 所需材料 |
| --- | --- | --- |
| 成本超预算原因 | 项目经理、财务负责人 | 成本明细、合同变更、外包/返工/差旅记录 |
| 报告修改次数多 | 项目经理、交付负责人 | 报告修改记录、客户反馈原文 |
| 验收风险高 | 项目经理、审核人 | 验收材料版本、客户确认记录 |
| 对外沟通口径 | 审核人、授权负责人 | 经复核后的事实、判断和建议 |

## 六、证据绑定

| 结论 | 证据 |
| --- | --- |
| P002成本风险 | 项目经营样例数据：预算28万元，已发生成本31万元 |
| P002进度风险 | 项目经营样例数据：计划45天，已用42天 |
| P002质量风险 | 项目经营样例数据：质量问题5，满意度3.1 |
| P002验收风险 | 项目经营样例数据：验收风险高 |
| P002需要人工复核 | 客户反馈：报告修改次数多，成本超预算仍未提前预警；是否需人工复核=是 |

## 七、案例结论

P002案例说明，本方案的AI工作台不是替代项目经理做最终判断，而是在经营会前把分散信息组织成可解释、可复核、可追溯的风险处理队列。

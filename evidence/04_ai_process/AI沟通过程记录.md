# AI沟通过程记录

## 一、协作概述

本次复赛在3小时内完成 `需求A_项目管理与经营分析AI助手`。采用**多AI工具协作 + 人工审核决策**的工作模式：

- **Codex**（OpenAI）：负责初稿生成和代码执行，擅长快速批量产出结构化文档和原型代码。
- **Claude Code**（Anthropic）：负责审核、提出创新方向和精修文档，擅长深度分析和架构设计。
- **人工（选手）**：负责方向决策、质量把关和最终确认，所有关键判断由人做出。

协作链路：Codex生成初稿 → 选手初步审查 → Claude Code深度审核并提出修改方案 → 选手确认修改方向 → Codex/Claude Code分工执行修改 → 选手最终确认提交。

## 二、第一轮：规划与初稿生成

### 2.1 选手 → Claude Code：比赛规划

选手首先将赛题材料包（需求A、企业背景、访谈纪要、规则清单、数据字典、提交规范等）提供给Claude Code，要求制定3小时的比赛规划，并为每一步附上给不同AI工具的具体Prompt。

Claude Code的规划产出：
- 分析了全部赛题材料，理解了需求A的核心——项目管理与经营分析AI助手
- 制定了6阶段时间规划：数据分析(40min) → 诊断报告(50min) → 数据规则+复核(30min) → JSON文件(20min) → AI过程记录(20min) → 打包(20min)
- 为每个阶段指定了工具分工和具体Prompt模板

**人工判断**：采纳了整体规划框架，但决定先让Codex一次性生成完整初稿，再逐步审核修改，而不是按阶段串行推进——因为Codex擅长批量生成。

### 2.2 选手 → Codex：生成完整初稿

选手将赛题材料提供给Codex，要求一次性生成完整提交包。Codex读取材料后输出了第一版，包括：
- `answer_manifest.json`、`workflow.json`
- `outputs/需求A_诊断报告.md`、`需求A_数据与规则处理.md`、`需求A_人工复核记录.md`、`需求A_项目资料缺失清单.md`
- `evidence/` 全部证据文件
- `prototype/index.html` 静态工作台

**Codex初稿特点**：
- 结构完整，所有必交文件均已生成
- 将方案定位为"项目经理经营会前AI工作台"
- 使用了官方P001-P008数据并完成了风险计算
- 设计了"感知-判断-生成-复核-证据"五层工作流
- 原型为三栏静态看板，可交互

**Codex初稿不足**（选手初审发现）：
- 特色不够突出，更像"标准合规答卷"而非"有亮点的方案"
- AI原生结构的深度不够，缺少Prompt链和防御性设计
- 原型缺少AI对话交互

## 三、第二轮：Claude Code深度审核

### 3.1 选手 → Claude Code：提交审查

选手将Codex的完整初稿提交给Claude Code，要求对照赛题评分维度进行深度审查，并指出所有需要修改的问题。

### 3.2 Claude Code审查发现（8个问题）

Claude Code逐文件审读后，输出了结构化审查报告：

| 编号 | 问题 | 严重度 | 具体说明 |
| --- | --- | --- | --- |
| 1 | AI沟通过程记录不够真实 | 严重 | 当时的记录写的是虚构的协作过程，而非实际工具对话 |
| 2 | workflow.json缺少Prompt链设计 | 中等 | 五层结构有了，但每层缺少具体的Prompt模板和输出约束 |
| 3 | 诊断报告缺少端到端可执行案例 | 中等 | 工作流只有表格描述，没有P002走完全流程的演示 |
| 4 | 原型不够"AI原生" | 中等 | 只有静态看板，缺少AI对话交互 |
| 5 | 数据处理缺少AI处理逻辑说明 | 中等 | 只有计算结果，没有Prompt设计 |
| 6 | 证据文件不足 | 低 | 缺少P002端到端案例的证据文件 |
| 7 | evidence_map.json路径不完整 | 低 | 新增文件未在地图中登记 |
| 8 | README未更新 | 低 | 没有提到后续新增的功能 |

同时，Claude Code提出了差异化策略——按"AI原生结构/人机协同/真实场景/证据质量/AI过程记录"五个评分维度，分别对应"普通做法"vs"脱颖而出的做法"的对比建议。

**人工判断**：全部采纳审查结论，确认修改方向为"定向增强，不推翻重来"。

## 四、第三轮：增强与修正

### 4.1 第一批修改：Codex执行

选手将Claude Code的审查报告转给Codex，要求按清单逐项修改。Codex完成了以下增强：

- workflow.json：为每层增加 `ai_prompt_design` 字段（Prompt策略、模板、预期输出）
- 诊断报告：增加第九节P002端到端案例
- 数据处理：增加第八节AI处理逻辑设计（含4个Prompt模板和P002示例）
- AI沟通过程记录：重写为多轮协作结构
- 新增 `evidence/01_diagnosis/P002_端到端案例.md`
- 更新 `evidence_map.json`
- 原型：增加AI对话模拟功能（悬浮按钮+对话面板+关键词匹配回复+快捷问题）

### 4.2 第二批修改：Claude Code执行

选手再次将Codex的修改结果提交给Claude Code做第二轮审查。Claude Code发现仍有改进空间，并融入了AI工程领域的前沿思想，直接在文件中进行了以下修改：

| 修改项 | 融入的思想 | 具体改动 |
| --- | --- | --- |
| workflow.json增加状态机和降级策略 | Agentic Scaffolding + 防御性AI编程 | 增加 `architecture.state_machine`（含10条状态流转规则）、每层增加 `fallback_strategy` 和 `state_transition` |
| workflow.json增加UX护栏设计 | UX即驾驭 + 隐形护栏 | 增加 `ux_as_harness`（5种界面护栏机制及其效果） |
| workflow.json增加Local-First说明 | 本地优先与数据主权 | 增加 `local_first_design`（解释为什么纯静态是刻意选择而非妥协） |
| workflow.json增加Skill/Memory解耦 | 技能与记忆的解耦架构 | 增加 `architecture.skill_memory_separation`（Skill/Memory/Guardrail三层分离） |
| 诊断报告增加架构选型说明 | 从裸奔到穿甲 | 增加8.1-8.3三个子节：架构选型、UX护栏、Local-First |
| 数据处理增加三层解耦说明 | 技能与记忆的解耦架构 | 在第八节增加Skill/Memory/Guardrail架构原则说明 |
| AI沟通过程记录完全重写 | — | 基于实际协作过程重写，记录真实的提问、追问、修正和人工判断 |

### 4.3 人工决策记录

以下是选手在整个过程中做出的关键人工判断：

| AI可能方向 | 人工判断 | 理由 |
| --- | --- | --- |
| 做完整项目管理平台 | 否决 | 赛题明确要求3小时最小闭环，不要扩大范围 |
| 用AI直接估算项目盈亏 | 否决 | 缺少合同付款节点，AI不能下确定性亏损结论 |
| 使用手工构造样例数据 | 否决 | 必须用官方P001-P008数据，否则产业场景真实性不足 |
| Demo接入真实AI API | 否决 | Local-First + 不依赖账号密钥是赛题要求 |
| 报告中承诺效率提升数字 | 否决 | 规则审核清单明确禁止未验证的承诺 |
| 推翻初稿全部重做 | 否决 | 定向增强效率更高，初稿结构本身合理 |
| 只做合规最低要求 | 否决 | 需要在架构、UX、AI原生设计上体现差异化 |
